# Руководство по тестированию InsulationMasterPro

## 1. Инструменты тестирования

### 1.1 DxfHeadlessRunner (Linux/Windows)

Консольная утилита для тестирования без AutoCAD.

```bash
# Сборка
dotnet build tools/DxfHeadlessRunner/DxfHeadlessRunner.csproj -c Release

# Запуск
dotnet run --project tools/DxfHeadlessRunner/DxfHeadlessRunner.csproj -c Release -- tests/4_fasada.dxf
```

### 1.2 AutoCAD-плагин (только Windows)

1. Собрать проект: `dotnet build InsulationMasterPro.csproj -c Release`
2. В AutoCAD: `NETLOAD` → выбрать `InsulationMasterPro.dll`
3. Команда `INS` — запуск раскладки
4. Команда `INS_DEL` — очистка (удаление раскладки + нумерации)

## 3. Контролируемые параметры

### 3.1 Перерасход (Overconsumption)

**Формула:** `(КупленоНового / ЧистаяПлощадьУтепления) × 100 - 100`

| Конфигурация | Целевой порог |
|---|---|
| 1 фасад | ≤ 10% |
| 4 фасада (с остатками) | ≤ 7% |

**Где смотреть:** строка `ОБЩИЙ ПЕРЕРАСХОД` в выводе headless runner или `diagnostics.txt`.

### 3.2 Синхронизация рядов (Row Sync)

**Что проверять:**
- Все фасады должны иметь **идентичные** высоты рядов
- Высоты берутся от Фасада 1 и тиражируются на остальные
- Stock Flush = OFF (все фасады синхронизированы)

**Где смотреть:**
```
[ROW-SYNC] Захвачена сетка: [450, 440, 600, ...] мм (снизу вверх)
[ROW-SYNC] Фасад 2: применяем сетку рядов от Фасада 1
```

**Как верифицировать:**
1. В выводе headless: сравнить строки `Высоты рядов:` для каждого фасада — должны совпадать
2. В AutoCAD: визуально проверить горизонтальные швы на углах

### 3.3 Минимальная высота ряда (MinRowHeight)

**Текущее значение:** 300 мм (v3.7.1)

**Что проверять:**
- Ни один ряд не должен быть < 300 мм
- Ряды 150 мм **НЕДОПУСТИМЫ**

**Где смотреть:** строка `Высоты рядов:` — все значения ≥ 300 мм.

### 3.4 Нумерация фасадов

**Порядок:** сверху вниз, слева направо.

**Где проверять (AutoCAD):**
- Номер фасада отображается слева от фасада
- Верхний левый фасад = №1
- Цвет: жёлтый (ColorIndex=2)
- Шрифт: жирный (`\W1.4;`), размер 500 мм

**Пример расположения:**
```
| 1 | 2 |      | 1 | 2 | 3 | 4 |
| 3 | 4 |  или |   |   |   |   |
```

### 3.5 Нумерация рядов

**Порядок:** снизу вверх (ряд 1 = нижний ряд).

**Позиция:** на оси симметрии высоты ряда.
- Формула: `Y = (MinY_ряда + MaxY_ряда + Height) / 2`
- Т.е. посередине высоты ряда, а НЕ по среднему Y плиток

**Формат:**
- Цвет: жёлтый (ColorIndex=2)
- Шрифт: жирный (`\W1.4;`), размер 250 мм

### 3.6 Технологические требования

**Что проверять (строка `TECH REQUIREMENTS: PASS/FAIL`):**

| Ограничение | Описание |
|---|---|
| C1 MinBlock | Минимальная ширина блока ≥ 200 мм |
| C12 Stagger | Перевязка швов между рядами |
| C12a CornerZone | Угловые зоны 200 мм |
| C13 ConsecRemnants | Не более 2 последовательных остатков |
| CH MinRowHeight | Все ряды ≥ 300 мм |

### 3.7 Движение склада

**Что проверять:**
```
Движение склада: вход=N  -Xисп  +Yсозд  =Zитого
```

- `вход` — остатки от предыдущих фасадов
- `-исп` — использовано остатков (чем больше, тем лучше)
- `+созд` — новые остатки от резов
- `итого` — общий склад после фасада

**Ключевые метрики:**
- Класс A (≥200 мм) — пригодны для любых рядов
- Класс B (150-199 мм) — только оконные зоны
- Мёртвые (<150 мм) — не могут быть использованы (должно быть 0)

### 3.8 INS_DEL (очистка)

**Что проверять (только AutoCAD):**
1. Запустить `INS` — убедиться что раскладка + нумерация появились
2. Запустить `INS_DEL` — убедиться что ВСЁ удалено:
   - Плитки (слой INS_TILES)
   - Остатки (слой INS_REMNANTS)
   - Перехлёсты (слой INS_OVERLAPS)
   - Нумерация фасадов и рядов (слой INS_FACADE_LABELS)
   - L-boot (слой INS_LBOOT)

## 4. Процедура полного тестирования

### 4.1 Headless-тест (Linux/Windows)

```bash
# 1. Собрать
dotnet build tools/DxfHeadlessRunner/DxfHeadlessRunner.csproj -c Release

# 2. Запустить на 4 фасадах
dotnet run --project tools/DxfHeadlessRunner/DxfHeadlessRunner.csproj -c Release -- tests/4_fasada.dxf

# 3. Проверить результаты:
#    a) ОБЩИЙ ПЕРЕРАСХОД ≤ 7%
#    b) Все ряды ≥ 300 мм
#    c) Row Sync: одинаковые высоты на всех фасадах
#    d) TECH REQUIREMENTS: PASS для всех фасадов
#    e) Мёртвый склад: 0 шт.
```

### 4.2 AutoCAD-тест (Windows)

1. **Подготовка:**
   - Собрать проект в Visual Studio или `dotnet build`
   - Открыть чертёж с несколькими фасадами
   - `NETLOAD` → загрузить `InsulationMasterPro.dll`

2. **Тест INS:**
   - Выполнить команду `INS`
   - Проверить:
     - [ ] Раскладка плитки отобразилась на всех фасадах
     - [ ] Нумерация фасадов: сверху вниз, слева направо
     - [ ] Нумерация рядов: снизу вверх, напротив середины ряда
     - [ ] Шрифт: жёлтый, жирный
     - [ ] Все ряды ≥ 300 мм (проверить визуально)
     - [ ] Горизонтальные швы совпадают на углах (Row Sync)

3. **Тест INS_DEL:**
   - Выполнить команду `INS_DEL`
   - Проверить:
     - [ ] Все плитки удалены
     - [ ] Вся нумерация удалена
     - [ ] Никаких артефактов не осталось

4. **Тест повторного запуска:**
   - Выполнить `INS` повторно
   - Проверить что результат воспроизводим

| Параметр | Значение | Файл | Описание |

| EnableRemnantPreAllocation | true | OrToolsModels.cs | Пред-аллокация остатков |

## 6. Известные ограничения

1. **MinRowHeight=300 увеличивает перерасход** — при MinRowHeight=150 перерасход был 3.77%, при MinRowHeight=300 — до 15.71% на тестовом чертеже. Это компромисс между технологическими требованиями и экономией материала.

2. **Сборка на Linux** — требует временной модификации csproj (net8.0 вместо net8.0-windows, отключение WPF/WinForms, исключение AutoCAD-зависимых файлов). НЕ коммитить эти изменения.

3. **Solver non-determinism** — точные значения overconsumption могут отличаться между запусками на ±0.5% из-за недетерминизма CP-SAT солвера.

## 7. Интерпретация diagnostics.txt / diagnostics.json

Файлы генерируются в `C:\DB_INS\` и содержат:
- Все входные параметры
- Высоты рядов и типы
- Координаты каждого блока
- Материальный баланс
- Результаты валидации

Используйте для детального анализа при расхождении ожидаемых и фактических результатов.
