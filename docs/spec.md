## 1. Назначение системы

**Insulation Layout Optimizer** — программная система для автоматизированной раскладки плит фасадного утеплителя на прямоугольном плоском фасаде с прямоугольными оконными проёмами в среде AutoCAD.

Система **обязана**:
- **Минимизировать** отходы материала и максимизировать повторное использование остатков со склада.
- **Соблюдать** технологические ограничения у окон, откосов, углов и краёв фасада.
- **Соблюдать жёсткий порядок** расчёта рядов: `BOTTOM_EDGE → MIDDLE → TOP_EDGE` с немедленным обновлением инвентаря.
- **Формировать** оконные G/U/L-элементы из единственного блока утеплителя (single-block, C16a).
- **Обеспечивать** непрерывное покрытие утеплителем по всем четырём сторонам периметра каждого окна (C17a).
- **Применять** адаптивную логику выбора высоты ряда и ротацию остатков.
- **Генерировать** детерминированный, воспроизводимый результат в форматах JSON, DXF, AutoCAD и XLSX.
- **Быть пригодной** для deterministic execution, CI, unit/regression-тестирования и IDE-LLM.

## 2. Границы системы (Scope)

### 2.1. Входит в scope

- Прямоугольные ортогональные фасады; прямоугольные оконные проёмы.
- **Многофасадная поддержка:** несколько фасадов на одном чертеже, синхронизация рядов, угловое замыкание.
- Автоматический подбор высот рядов (адаптивная логика, диапазон 150–600 мм).
- Сегментация фасада по окнам; генерация паттернов укладки.
- Повторное использование остатков склада (as-is и с подрезкой), включая ротацию на 90°.
- Немедленное использование «свежих» вырезок из краевых рядов (C15).
- Выпуск блоков за вертикальный угол фасада.
- Г-образные (L-boot) и П-образные (U-boot) элементы; single-block-правило (C16a).
- Смешанные комбинации `REMNANT – NEW – REMNANT` при соблюдении лимитов C13.
- Нахлёст на оконную раму 20 мм **внутрь** проёма.
- JSON I/O, DXF/AutoCAD-экспорт, Excel-отчёт, логирование, diagnostics, fallback-каскад.

### 2.2. Вне scope

- Теплотехнический расчёт; подбор марки утеплителя; расчёт клея, армирования, крепежа.
- IFC/BIM-экспорт; 3D-раскладка; криволинейные фасады; окна произвольной формы.

## 7. Каноническая геометрия окна

### 7.1. Световой проём

Окно задаётся прямоугольником:

```
w_k = (x_k^L, x_k^R, y_k^B, y_k^T)
```

где координаты — границы светового проёма в мм (тип `int`).

### 7.2. Эффективный проём

С учётом `WindowOverlap = δ = 20 мм`:

```
w_k^eff = (x_k^L + δ,  x_k^R − δ,  y_k^B + δ,  y_k^T − δ)
```

**КАНОНИЧЕСКИЙ СМЫСЛ ЗНАКА (единственно верный):**

Нахлёст означает, что утеплитель заходит ЗА раму **внутрь** оконного проёма на δ мм.
Эффективный проём `w_k^eff` определяет **пустую зону** внутри окна (не покрытую утеплителем).
Она **меньше** светового проёма на 2δ по каждому измерению.

| Сторона | Формула | Физический смысл |
|:---|:---|:---|
| Левая | `x_k^L + δ` | Утеплитель заходит на δ мм **вправо** внутрь проёма |
| Правая | `x_k^R − δ` | Утеплитель заходит на δ мм **влево** внутрь проёма |
| Нижняя | `y_k^B + δ` | Утеплитель заходит на δ мм **вверх** внутрь проёма |
| Верхняя | `y_k^T − δ` | Утеплитель заходит на δ мм **вниз** внутрь проёма |

> **Любая интерпретация, при которой эффективный проём БОЛЬШЕ светового (знак расширяет границы наружу), является ошибкой.**

### 7.3. Запретная зона для стыков (CornerZone)

CornerZone строится **от края нахлёста**, а не от границы светового проёма:

```
ForbidX_k = [x_k^L + δ − γ,  x_k^L + δ + γ]  ∪  [x_k^R − δ − γ,  x_k^R − δ + γ]
```

где `δ = WindowOverlap = 20 мм`, `γ = CornerZone = 150 мм`.

**Подстановка числовых значений:**

```
Левая зона:   [ x_k^L − 130,  x_k^L + 170 ]
Правая зона:  [ x_k^R − 170,  x_k^R + 130 ]
```

> Стык на расстоянии **ровно 150 мм** от края нахлёста — **допустим**.  
> Стык **ближе 150 мм** от края нахлёста — **запрещён**.  
> Единая знаковая конвенция применяется во всех формулах, сегментации, генерации паттернов и валидаторах.

### 7.4. ASCII-схема геометрии окна

```
       x_k^L−130  x_k^L   x_k^L+20   x_k^L+170
            │         │         │         │
════════════│▓▓▓▓▓▓▓▓▓│▒▒▒▒▒▒▒▒▒│▓▓▓▓▓▓▓▓▓│════════ ... ════│▓▓▓▓▓▓▓▓▓│═══
            └─────────┘         └─────────┘                 └─────────┘
            Запрет 150мм     нахлёст 20мм                   Запрет 150мм
           (стыки нельзя)   (внутрь окна)                  (стыки нельзя)
```

## 8. Классификация рядов

Каждый ряд классифицируется по вертикальному положению относительно окна:

| Тип ряда | Определение | Геометрия |
|:---|:---|:---|
| `BOTTOM_EDGE` | Пересекает нижнюю границу окна (`y_k^B`) | Формируются BL, BR Г-элементы или нижний U-boot |
| `MIDDLE` | Полностью расположен внутри высоты окна | Пусто в зоне проёма, заполнение только боковин |
| `TOP_EDGE` | Пересекает верхнюю границу окна (`y_k^T`) | Формируются TL, TR Г-элементы или верхний U-boot |
| `NORMAL` | Вне высоты окна | Стандартная раскладка по всей ширине |

## 9. Порядок расчёта рядов (CRITICAL)

### 9.1. Жёсткая последовательность

Порядок расчёта является **обязательным и неослабляемым (C14)**:

```
BOTTOM_EDGE → MIDDLE → TOP_EDGE
```

Алгоритм обрабатывает каждый уровень для всех окон, обновляя inventory после каждого слоя.

### 9.2. Псевдокод обработки окна

```
Inventory = InitialInventory

For each window w:
    // Шаг 1: нижний краевой ряд
    SolveRow(BOTTOM_EDGE, w, Inventory) → produce_bottom
    Inventory.Add(produce_bottom)     // немедленно!

    // Шаг 2: средние ряды
    SolveRow(MIDDLE, w, Inventory) → produce_middle
    Inventory.Add(produce_middle)

    // Шаг 3: верхний краевой ряд
    SolveRow(TOP_EDGE, w, Inventory) → produce_top
    Inventory.Add(produce_top)
```

### 9.3. «Свежие вырезки» (C15)

Вырезка из BOTTOM_EDGE, удовлетворяющая порогам годности (`width ≥ 200 мм AND height ≥ 150 мм`):

1. Немедленно добавляется в Inventory.
2. Доступна для использования в MIDDLE и TOP_EDGE этого же фасада.
3. Используется не более одного раза (GUID-уникальность).

> Нарушение порядка `BOTTOM → MIDDLE → TOP` — **блокирующий дефект E_ROW_ORDER_VIOLATION**.

## 10. Адаптивная высота ряда

### 10.1. Диапазон и дискретизация

Любой ряд может иметь высоту от **150 до 600 мм**. Высота ряда задаётся **целым числом миллиметров**:

```
H ∈ ℤ,  150 ≤ H ≤ 600
```

Требование кратности 50 мм **отменяется**.

> **Обязательное правило:** ядро системы работает в канонических единицах `int` мм, поэтому выбор высоты ряда обязан выполняться в точных миллиметрах без дополнительного округления к шагу 50 мм.

### 10.2. Алгоритм выбора высоты RowHeightForecaster

**Шаг 1.** Построить гистограмму высот остатков на складе (с учётом возможности ротации).

**Шаг 2.** Для каждой кандидатной высоты `H ∈ ℤ, 150 ≤ H ≤ 600` вычислить суммарную доступную длину:

```
L_available(H) = Σ width_r  для всех остатков r:
                 usable_height(r, H) = true
```

где `usable_height(r, H) = true`, если:
- либо `height_r ≥ H`,
- либо после ротации на 90° `rotated_height_r ≥ H`.

**Шаг 3.** Вычислить коэффициент покрытия:

```
Coverage(H) = L_available(H) / W_facade
```

**Шаг 4.** Для каждой кандидатной высоты вычислить оценку отходов `Waste(H)` и выбрать высоту по правилу:

```
H_row = argmax_H { H | Coverage(H) ≥ 0.3  OR  Waste(H) < Waste(600) }
```

При равных условиях — выбирается **максимально высокий** допустимый ряд (предпочтение H = 600 мм).

### 10.3. Two-pass обработка dead zone (v14.1)

Когда `TileHeight = 600` и `MinRemnantToSave = 150`, высоты h ∈ [451..599] порождают leftover ∈ [1..149] мм — слишком мало для сохранения на складе. Система применяет **двухпроходную стратегию**:

**Pass 1 — жёсткий запрет (hard ban):**
```
∀ активный ряд i:  h_i = 600  ∨  h_i ≤ 450
```
Таймаут: `min(15 сек, baseTimeout × 3)`. Ограничение числа рядов: `maxActiveRows = ⌈H_facade / TileHeight⌉ + 2`.

**Pass 2 — fallback (тяжёлый soft penalty):**
Если Pass 1 INFEASIBLE (геометрия окон не позволяет избежать dead zone):
```
min J_1 = Σ_i [ pen(i) · |h_i − 600| ]  +  N_r · RowCountPenalty  +  Σ_i [ DZ(i) · leftover_i · rowPosWeight × 10 ]
```
Штраф пропорционален leftover и позиции ряда, cap 2 000 000. Солвер **крайне редко** выбирает dead zone, но может сделать это при жёстких оконных ограничениях.

- `pen(i) = WindowAdjHeightPenalty = 5000` для рядов, прилегающих к окнам.
- `pen(i) = NormalHeightPenalty = 600` для остальных рядов.
- `DZ(i) = 1`, если `TileHeight - h_i ∈ (0, MinRemnantToSave)`, иначе `0`.

| Высота ряда | Leftover | Pass 1 | Pass 2 |
|:-----------:|:--------:|:------:|:------:|
| 600 | 0 | ✅ Допустима | ✅ Допустима |
| 450 | 150 | ✅ Допустима | ✅ Допустима |
| 480 | 120 | ❌ Запрещена | ⚠ Тяжёлый штраф |
| 530 | 70  | ❌ Запрещена | ⚠ Тяжёлый штраф |

### 10.4. Точное закрытие оконной зоны по высоте

Утеплитель заходит на δ мм **внутрь** оконного проёма. Поэтому зона покрытия от низа фасада простирается до `y_k^B + δ`:

```
Зона покрытия снизу:  0 → y_k^B + δ
```

где `δ = WindowOverlap = 20 мм`.

### 10.5. Запрет на обрезку рядов по границам окон (Trim-to-Target отменён)

Для формирования цельных Г-образных элементов (L-boots) с корректной полкой ≥ 150 мм **запрещается** привязывать горизонтальные швы рядов к верхним и нижним границам окон.

### 10.6. Intra-Row BinPack консолидация (v14.2)

**Цель:** устранить ситуацию, когда несколько мелких `[New]` блоков в одном ряду потребляют по отдельной физической плите.

**Алгоритм:**
1. Собрать все блоки типа `[New]` с шириной `< TileWidth` из всех сегментов текущего ряда.
2. Отсортировать по убыванию ширины (BFD).
3. Упаковать в минимальное число физических плит 1200 мм алгоритмом Best Fit Decreasing.
4. Для каждого бина с >1 блоком: anchor-блок остаётся `[New]`, остальные конвертируются в `[CutRemnant]` с проверкой C13.
5. После `UpdateStockAfterRow` — удаляются дублирующие остатки виртуальной цепочки.

**Эффект (f_test.dxf):** Overconsumption 6.1% → 0.8%, NewTiles 160 → 152, SolveTime −39%.

## 11. Ротация плит и остатков

- Ротация на 90° разрешена для любых рядов, если это **экономически целесообразно**.
- Для каждого остатка проверяются оба варианта (прямой и повёрнутый).
- **Условие предпочтения ротации:** `height_rotated = H_row` (точное совпадение без реза) OR `waste(rotated) < waste(normal)`.
- Повёрнутый блок помечается `IsRotated = true` в DTO.

## 12. BOTTOM_EDGE и TOP_EDGE рядов

### 12.1. Принцип «сплошной ряд + вычитание проёма»

Краевые ряды **обязаны**:
1. Заполняться как сплошные ряды от левого до правого края фасада.
2. Затем из тела блока вычитается эффективный проём (Clipper2 Boolean Difference).
3. Полученный Г- или П-элемент — результат **одного исходного блока**.

> Запрещено формировать L-boot как два отдельных прямоугольных блока (C16a).

### 12.2. Обработка вырезок

| Размер вырезки | Действие |
|:---|:---|
| `width ≥ 200 мм AND height ≥ 150 мм` | Добавить в Inventory (склад) |
| Иначе | Отход (мусор) |

---

## 13. MIDDLE-ряды: боковые заполнения

### 13.1. Правила

1. Зона эффективного проёма `[x_k^L + δ, x_k^R − δ]` остаётся **пустой**.
2. Заполняется только левая боковина: от `0` до `x_k^L + δ`.
3. Заполняется только правая боковина: от `x_k^R − δ` до `W_facade`.
4. Последний блок у края эффективного проёма: ширина **≥ 150 мм** (`MinBlockWidthNearWindow`).
5. Перевязка проверяется **по всей ширине фасада**, включая виртуальные стыки.

> **Внимание (v13.4):** `ValidateMiddleRowsEmpty` обязан использовать `effLeft = MinX + δ`, `effRight = MaxX − δ` (нахлёст **внутрь** проёма).

> Неполное заполнение боковин в MIDDLE-рядах — **блокирующее нарушение C17a (E_WINDOW_PERIMETER_NOT_COVERED)**.

## 14. Доменная модель L-boot и U-boot

### 14.1. L-boot (Г-образный элемент)

- **Single-block (C16a):** L-boot порождается **ровно одним** блоком утеплителя.
- Обе полки (горизонтальная и вертикальная): **≥ 150 мм** (`LBootMinShelf`).
- Геометрия восстанавливается из исходного блока операцией Boolean Difference.
- Доменная сущность отражается в `lbootElements[]`.

```
Исходный блок (1200×600):
┌──────────────────────────────┐
│   L-boot (остаётся)   │вырез │
│  горизонтальная полка ≥150мм │(проём)│
├───────────────────────┘      │
│  вертикальная полка ≥150мм   │
└──────────────────────────────┘
```

### 14.2. U-boot (П-образный элемент)

U-boot разрешён для узких окон, когда одна плита перекрывает **оба угла** одновременно.

### 14.3. Правило единого блока (C16a) — формально

> Любой G-элемент обязан быть геометрически порождён **ровно одним** блоком утеплителя. Стык по линии внутреннего угла проёма — **запрещён навсегда**, включая fallback-режим.

## 15. Полное покрытие периметра окна (C17a)

Для каждого окна `w_k` объединение проекций всех блоков утеплителя, соприкасающихся с каждой стороной `w_k^eff`, обязано образовывать **непрерывный отрезок** без «голых» участков.

> **C17a не ослабляется ни в одном fallback-шаге.**

## 16. Работа с остатками

- Каждый остаток имеет уникальный `id` (GUID) и используется **не более одного раза**.
- Остатки `width < 200 мм OR height < 150 мм` — отход; на склад не поступают.

### 16.1. Суб-нарезка и трассировка

Остаток может быть докрован повторно (рекурсивно), пока его размер ≥ `MinRemnantToSave`.

| Поле | Тип | Описание |
|------|-----|----------|
| `CutHistory` | `string` | Цепочка нарезки: `"Плита 600→210+390→210+180"` |
| `ParentRemnantId` | `Guid?` | GUID родительского остатка |
| `Source` | `string` | Источник создания остатка |

### 16.2. Нумерация блоков (v14.3, формат X.Y.NNN.ZZ)

| Компонент | Значение | Пример |
|-----------|----------|--------|
| X | Номер фасада (1-based) | `1` |
| Y | Номер ряда (1-based, снизу вверх) | `3` |
| NNN | Порядковый номер плиты в ряду | `014` |
| ZZ | Порядковый номер остатка от плиты | `01`, `02` |

### 16.4. Материальный баланс фасада

| Метрика | Формула |
|---------|--------|
| Перерасход | `TotalNewMaterialArea / NetInsulationArea × 100% − 100%` |
| КПД раскроя | `NetInsulationArea / (TotalNewMaterialArea + ReusedArea) × 100%` |
| Экономия от остатков | `ReusedArea / NetInsulationArea × 100%` |

### 16.5. Статусы остатков

| Статус | Описание | Сохраняется в БД |
|--------|----------|------------------|
| `FromStock` | Взят из `remnants.json` | Удаляется после использования |
| `Created` | Новый остаток от раскроя | **Да** |
| `CreatedAndReused` | Создан при раскрое и тут же использован | **Нет** |

## 18. Математическая модель

### 18.1. Геометрическое представление фасада

```
F = [0, W_F] × [0, H_F]   (координаты в мм, тип int)
W = { w_k = (x_k^L, x_k^R, y_k^B, y_k^T) | k = 1…N_w }
```

### 18.2. Эффективный проём (δ = 20 мм)

```
w_k^eff = (x_k^L + δ,  x_k^R − δ,  y_k^B + δ,  y_k^T − δ)
```

### 18.6. Целевые функции

**Этап 1 — RowHeightForecaster (CP-SAT):**
```
min J_1 = Σ_i [ pen(i) · |h_i − 600| ]  +  N_r · 1000  +  Σ_i [ DZ(i) · 10000 ]
```

**Этап 2 — LayoutEngine (CP-SAT):**
```
min J_2 = Σ_{b ∈ NEW} A_b  +  N_trim · 1_000_000  −  Σ_{b ∈ REMNANT} A_b · 2  −  N_asis · 2_000_000
```

## 20. Pipeline (Порядок выполнения)

```

     │
     ▼

     │
     ▼

     │
     ▼
[2] RowHeightForecaster (CP-SAT, Этап 1)
    └── Адаптивный выбор { h_i } по Coverage(H), Waste(H), штрафам
    │
    ▼
[3] RowSegmenter
    └── Разбивка каждого ряда на сегменты с учётом w_k^eff и CornerZone
    │
    ▼
[4] OrderedRowOptimizer (CP-SAT, Этап 2)
    │
    ├─▶ [4a] BOTTOM_EDGE Layer
    │       ├── Сплошной ряд → Boolean Difference → L/U-boot (single-block)
    │       └── Inventory.Add(свежие вырезки)
    │
    ├─▶ [4b] MIDDLE Layer
    │       ├── Заполнение только боковин; w_k^eff = пусто
    │       └── Inventory.Add(остатки)
    │
    └─▶ [4c] TOP_EDGE Layer
            ├── Сплошной ряд → Boolean Difference → L/U-boot (single-block)
            └── Inventory.Add(свежие вырезки)
    │
    ▼
[5] Postprocessor
    ├── GeometryInvariantValidator    — C1, C2, C3
    ├── CornerZoneValidator           — C12a

    ├── LBootValidator                — C16 + E_LBOOT_SHELF_SIZE

    ├── RemnantsSequenceValidator     — C13

    ├──▶ CAD Adapter  →  DXF / AutoCAD (MText 60мм, 2 строки: размер + X.Y.NNN.ZZ)
```

## 32. Многофасадная поддержка (Multi-Facade)

- **Сортировка:** сверху вниз по Y, затем слева направо по X
- **Синхронизация рядов:** мастер-фасад №1 → тиражирование на остальные
- **Corner Interlock:** нечётные фасады — прямой выпуск, чётные — инвертированный
- **Маркировка:** слой `INS_FACADE_LABELS`, высота шрифта 300/150 мм

### 32.7 Управление складом при многофасадной раскладке

| Класс | Минимальная сторона | Применение |
|-------|--------------------|-----------| 
| A | ≥ 200 мм | Любые ряды |
| B | 150–199 мм | Только оконные зоны |
| Отход | < 150 мм | Не сохраняется |
