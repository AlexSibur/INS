# E_LBOOT_SHELF_SIZE ошибки блокировали отрисовку при валидном решении (110 ошибок → return)

**Date:** 2026-03-30 00:17
**Files:** PluginCommands.cs
**Severity:** critical

## Problem

Команда INS находила оптимальное решение (Status=Optimal, 1130 tiles, 106с), но
возвращалась до отрисовки из-за 110 "блокирующих ошибок" `E_LBOOT_SHELF_SIZE`.
Пользователь видел: "Ошибки при обработке (решение OR-Tools не получено или невалидно)".
Ни один блок не отрисовывался на чертеже.

## Root Cause

`PluginCommands.RunLayout()` делил ошибки на 2 категории:
- `E_OVERCONSUMPTION` → не блокирует
- **Всё остальное** → блокирует (→ `return` до `VisualizationEngine`)

`E_LBOOT_SHELF_SIZE` — это **валидационное замечание** о том, что вертикальная полка
Г-образного элемента (L-boot) получилась 30-50 мм вместо минимальных 150 мм.
Это нормально для определённых конфигураций рядов и не означает, что решение невалидно.

Postprocessor добавлял `E_LBOOT_SHELF_SIZE` в `result.Errors` (а не `result.Warnings`),
и `PluginCommands` не имел механизма отличить "решение невалидно" от "решение найдено,
но есть замечания по качеству".

С 4 фасадами × 12 окон × несколько L-boot углов = 110 таких ошибок, и каждая блокировала.

Headless runner не воспроизводил баг — он не блокирует рендеринг по ошибкам.

## Solution

Переименовали `IsOverconsumptionError()` → `IsNonBlockingError()` и расширили фильтр:

```csharp
private static bool IsNonBlockingError(string error)
{
    return error.StartsWith("E_OVERCONSUMPTION", ...) ||
           error.StartsWith("E_LBOOT_SHELF_SIZE", ...);
}
```

Теперь `blockingErrors` = только **реальные** ошибки (решение не найдено, критические сбои).
Замечания `E_LBOOT_SHELF_SIZE` и `E_OVERCONSUMPTION` показываются пользователю
с группировкой ("E_LBOOT_SHELF_SIZE: 110 шт."), но не блокируют отрисовку.

## Prevention

- При добавлении новых `E_*` кодов в Postprocessor — **решить заранее**:
  это блокирующая ошибка или валидационное замечание?
- Блокирующие ошибки: "решение не найдено", "нет рядов", критические сбои.
- Замечания: `E_LBOOT_SHELF_SIZE`, `E_OVERCONSUMPTION`, `E_OVERLAP_*`.
- Рассмотреть рефакторинг: использовать `ErrorSeverity` enum вместо строкового prefix-matching.
- Всегда тестировать конечный путь (AutoCAD plugin), а не только headless runner.
