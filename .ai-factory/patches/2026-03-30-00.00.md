# MergeResults не пробрасывал DiagInput/DiagSolution → diagnostics.txt не создавался

**Date:** 2026-03-30 00:00
**Files:** LayoutEngine.cs, PluginCommands.cs
**Severity:** critical

## Problem

После запуска INS в AutoCAD:
1. Файл `C:\DB_INS\diagnostics.txt` не создавался — пользователь не мог видеть результаты диагностики.
2. `SolverStatus` отображался как пустая строка, `OptimizationMode` — как "Greedy" (вместо "OR-Tools"), `SolveTimeMs` — 0.
3. `OverConsumptionExceeded` всегда `false`, даже когда отдельные фасады превышали лимит 7%.
4. Пользователь считал что "решение не найдено", хотя на самом деле оптимизация выполнялась успешно.

Headless runner (`DxfHeadlessRunner`) работал корректно — вызывает `DiagnosticLogger` напрямую.

## Root Cause

`LayoutEngine.MergeResults()` (строки 358–378) объединяет результаты всех фасадов в один `LayoutResult`,
но пропускал 6 критических полей:

- `DiagInput` (FacadeInput) — оставался `null`
- `DiagSolution` (OrToolsSolution) — оставался `null`
- `SolverStatus` (string) — оставался `""` (default)
- `SolveTimeMs` (long) — оставался `0`
- `OptimizationMode` (string) — оставался `"Greedy"` (default)
- `OverConsumptionExceeded` (bool) — оставался `false`

В результате `PluginCommands.WriteDiagnosticsSafe()` видел `DiagInput == null` и печатал
"Диагностика не сформирована" вместо вызова `DiagnosticLogger.WriteDiagnostics()`.

Цепочка: `ProcessWithOrTools` ставит все 6 полей на per-facade `LayoutResult` (строки 300–302) →
`MergeResults` теряет их → `Process()` возвращает `LayoutResult` с null-диагностикой →
`WriteDiagnosticsSafe` не вызывает `DiagnosticLogger` → файл не создаётся.

## Solution

1. **`LayoutEngine.MergeResults()`** — добавлено пробрасывание всех 6 полей:
   - `DiagInput`, `DiagSolution` — last-facade-wins (последний фасад)
   - `SolverStatus`, `OptimizationMode` — последнее непустое значение
   - `SolveTimeMs` — суммирование
   - `OverConsumptionExceeded` — OR-логика (true если хотя бы один фасад превысил)

2. **`PluginCommands`** — добавлен `[FIX]` logging:
   - `LogFix()` helper — пишет и в AutoCAD command line, и в `C:\DB_INS\database.log`
   - Log параметров оптимизации перед запуском
   - Log результата после `engine.Process()` (status, mode, tiles, errors)
   - Log содержимого `WriteDiagnosticsSafe` при null-диагностике (для будущей отладки)
   - Log количества блокирующих ошибок

## Prevention

- При добавлении полей в `LayoutResult` — **всегда** проверять `MergeResults()` и добавлять
  соответствующее слияние. Текущий код использует ручное перечисление полей — легко забыть.
- Рассмотреть рефакторинг: вынести per-facade данные (DiagInput/DiagSolution) в отдельный
  список `List<FacadeDiagnostics>` на LayoutResult, чтобы MergeResults просто AddRange-ил.
- Добавить unit-тест: `MergeResults` не теряет поля (проверить все non-default значения).
- Headless runner не воспроизводит этот баг — всегда тестировать конечный путь (AutoCAD plugin).
